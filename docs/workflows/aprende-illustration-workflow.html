Workflow thesis · illustration authoring

How Criar Sin Culpas produces bespoke hero illustrations at scale.

A two-lane operating model that keeps illustration authoring in GenSpark, where design consistency lives, and article implementation in Cursor, where the codebase lives. The result: every guide gets a bespoke landscape metaphor, none of them drift from the system, and the codebase never becomes a dumping ground for one-off SVG decisions.

Thesis
The illustrations are brand assets, not code. They are designed once, versioned in git, and consumed by the codebase through a single stable path convention. The design system is the source of truth. Cursor never invents; Cursor only places.

01The two lanes

Lane A

GenSpark · design authoring

Where bespoke illustration is created
  • Luis briefs the article. Slug, title, core emotional tension in one sentence.
  • GenSpark drafts 2–3 landscape metaphor variations using the same construction rules as "La ola" — 800×480 canvas, 1.9pt navy line, dusty washes offset 2–4°.
  • Luis selects one. GenSpark finalizes to assets/illustrations/hero-<slug>.svg.
  • The manifest and design-system README update automatically so the metaphor is documented and future guides can reference the pattern.
Lane B

Cursor · code implementation

Where the illustration is placed on the page
  • Cursor implements the article surface once. Uses the handoff bundle: ArticleSection, TipBox, PediatraCallout, tokens CSS.
  • Each new article specifies its slug. The <img> inside .cs-article-hero resolves to assets/illustrations/hero-<slug>.svg — either via CMS field or convention.
  • No design decisions live in code. Cursor never generates SVGs, never picks palettes, never invents new components.
  • Adding a new hero is a file drop + one CMS field, not a PR.

03Why this is the scalable answer for the whole site

Consistency by design, not by luck

Illustrations are authored in one place, against one system, following one set of construction rules. There is no path where a developer's ad-hoc SVG ends up in production. The 12th guide will look like the 1st.

Editorial velocity stays high

A new guide ships in the time it takes to brief, review, and drop a file. Engineering does not become a bottleneck for every illustration decision. Marketing owns the visual authoring loop end-to-end.

The codebase stays clean

One ArticleSection component. One hero container. One path convention. Engineering owns the reader shell; illustrations are just files it consumes. No component sprawl, no design tokens defined in TSX.

The system extends beyond articles

The same model applies to protocol cards, email templates, social-share images, and eventual print work. The landscape-metaphor library is a brand asset, not an article asset. It works wherever the brand shows up.

Version history is preserved

Every illustration lives in git as an SVG. Every design decision has a compare-canvas artifact. The brand's visual history is inspectable, revertible, and legible to future team members.

Cursor stays in its lane

Language models are excellent at implementing existing patterns and terrible at inventing systematic bespoke visuals. This workflow uses each tool where it is strongest. Neither is asked to do the other's job.

What Luis is asking the systems architect to sign off on

  1. The path convention. Every hero illustration lives at assets/illustrations/hero-<slug>.svg in the production repo. Cursor references it by convention, not by CMS URL.
  2. The manifest file. A JSON manifest (assets/illustrations/manifest.json) listing every hero — slug, metaphor name, status. Cursor reads it to know what exists; humans read it to know what is still to design.
  3. The one-time article-reader implementation. Cursor builds the reader surface once, from the handoff bundle already delivered. All future guides reuse it — no per-article layout work.
  4. The briefing loop. Luis returns to GenSpark for every new guide's hero. Not for the article implementation, not for tokens, not for components — only for the bespoke illustration and its inclusion in the design system.
